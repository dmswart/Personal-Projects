# Warping Pictures Nicely

A static HTML/JS/D3 implementation of David Swart's harmonic-map warping
algorithm ("Warping Pictures Nicely", Bridges 2011) — warps a grid from an
arbitrarily-shaped source region to a circle or regular polygon, then uses
the converged mesh to warp an actual image.

Paper: [Warping Pictures Nicely](https://archive.bridgesmathart.org/2011/bridges2011-303.pdf)
(Bridges 2011 Mathematical Art Conference Proceedings, pp. 303-310).

## Running it

Web Workers require the app to be served over `http://`, not opened via
`file://`. From this folder, run any static server, for example:

```powershell
python -m http.server 8080
```

then open `http://localhost:8080/`.

(If you use Python's built-in server on Windows, it may serve `.js` files
with the wrong `Content-Type`, which can break the Worker. Most other
servers — VS Code's Live Server, `npx serve`, nginx, GitHub Pages, etc. —
set this correctly. If you're stuck with Python on Windows, use the included
`serve.py` instead, which fixes the MIME type and disables caching:

```powershell
python serve.py 8080
```

Note: if you already hit the error with `http.server`, your browser may
have cached the bad `Content-Type` response — do a hard refresh or open a
new tab after switching servers.)

## Using the app

1. **Source Shape** — either a plain rectangular grid, or a black & white
   silhouette image (the black region becomes the mesh's shape; check
   "Invert" if your shape is white-on-black). Set the grid resolution
   (rows/columns).
2. **Destination Shape** — a circle or regular polygon.
3. **Build Mesh** — samples the shape, builds the mesh, and shows the
   initial (unrelaxed) placement in the Destination panel.
4. **Go** — runs the relaxation iterations in a Web Worker (off the UI
   thread), animating the Destination panel as it converges. **Cancel**
   stops it early; the mesh up to that point is still usable.
5. **Map Imagery** — once converged, choose a source image and click
   "Map Image to Destination" to warp it onto the destination shape via
   the converged mesh, then download the result.

## File layout

- `index.html` / `css/style.css` — layout and controls only.
- `js/geometry.js` — vector math + `Circle`/`RegularPolygon` boundary shapes.
- `js/mesh.js` — grid construction, silhouette sampling, boundary tracing,
  initial placement.
- `js/algorithm.js` — the core per-vertex relaxation step and the
  conformality (convergence) metric.
- `js/worker.js` — runs the iteration loop off the main thread; supports
  cancellation.
- `js/draw.js` — D3 rendering of the source/destination panels.
- `js/imageMap.js` — final triangle-textured image warp + PNG export.
- `js/main.js` — UI wiring/orchestration only.

## Known limitations

- Boundary correspondence between the source shape's outline and the
  destination shape's perimeter is derived by tracing the source contour
  and distributing points proportionally by arc length; shapes with very
  thin appendages or tight notches (e.g. the "X" example in the paper) can
  still show local crowding, matching the limitations discussed in the
  original paper (Section 4).
